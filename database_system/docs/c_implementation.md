## 类型与语义的数据流

`analyze()` 按语句种类检查结构和名称，再用显式栈后序检查表达式类型，避免长表达式耗尽 Python 递归栈。检查顺序仍为左子树、右子树、父节点。标识符通过 Catalog 解析，成功后标注 `resolved_type`；每个成功检查的表达式标注 `expr_type`。返回值就是传入列表，结构序列化仍不包含这些标注。

类型判断集中在 `types.py`。INSERT 使用显式 `lit_type`，不把 Python 的布尔值误当整数。所有 VARCHAR 字面量按 UTF-8 字节数检查长度；85 个汉字恰好 255 字节，再添加一个 ASCII 字符就超过限制。

INSERT 先验证列值数量、重复列、未知列和完整覆盖，再逐值收集类型与长度错误。同一个值可产生两条独立诊断，按位置稳定排序。结构错误可以首错停止。SELECT／INSERT 的字符串列名没有单独位置，因此使用语句首；表达式、值和重复列定义使用对应 AST 节点位置。直接调用 `Catalog.create_table()` 时，诊断按契约使用首列位置；私有校验参数让 SQL 语义入口保留具体重复列的位置，公开接口不变。

语义阶段不调用 `create_table()`，不求值常量，不处理跨语句提交。`analyze([CREATE, SELECT], catalog)` 不让第二条语句看到未提交的表；D 必须逐句编排。短路分支也必须完成类型检查；类型正确的除零和溢出表达式通过语义阶段。

`checked_int_arithmetic()` 检查两个操作数及结果的 32 位范围，除法使用绝对值整数整除后恢复符号。D 的优化器在算术失败时保留子树，执行器在实际求值时转换成执行错误。

## Catalog 的三种后端

内部表索引使用小写名称，Schema 保留首次注册的名字、列顺序及源码位置。输入列与查询结果均复制，防止外部绕过提交修改目录；`snapshot()` 深复制且不保留任何文件或存储引用。

| 构造方式 | 行为 |
|---|---|
| `Catalog()` | 纯内存目录，不访问文件 |
| `Catalog(json_path)` | 加载 JSON；缺失或零字节文件视为空；首次成功建表才写文件 |
| `Catalog(storage=storage)` | 要求系统表已经引导完成；通过表级接口加载系统目录 |

JSON 根为 `tables` 数组，表按小写名称排序，列保持原顺序。列用 `ColumnDef.to_dict()` 保存，包括节点名和位置。非法 JSON、重复键或非法结构报 `ExecuteError`，不静默重建。提交时写同目录临时文件，关闭后用 `os.replace()` 替换；替换成功才更新内存。父目录由调用方准备。

系统目录固定为六列：表名、列名、列类型、列序号、源码行和源码列，每个用户列对应一条记录。系统表结构在代码中直接定义，不查询或登记自身。加载时验证列序号连续、表列合法、物理表存在；保留原始大小写和列位置。用户接口不暴露系统表。

数据库建表严格按以下顺序进行：逻辑预检 → B 检查容量并创建物理表 → 写入每列目录记录 → B 刷盘 → 更新内存目录。中途 I/O 失败不会宣称内存提交成功，但不承诺回滚已经写入的物理数据。

59 张用户表的物理限制由 B 检查。当前测试用表级替身验证 C 正确传播该错误；这不等于 B 的真实容量管理已经通过验收。JSON 和内存目录不套用这个物理限制。

## 物理页、缓存和空闲链

`PageStore` 构造时打开文件。新文件或零字节文件初始化页 0；已有文件校验页对齐、魔数、版本、保留字段和空闲链。页 0 头为 `<4sHHII>`，数据页布局由 B 解释，C 不操作槽或用户记录。

`BufferPool` 使用有序字典保存缓存对象。LRU 命中会移到末尾，FIFO 命中不改变次序。默认容量 64，允许容量 1。合法取页请求计入命中／未命中；构造校验、直接读写和刷盘不计数。淘汰时完成脏页写回、移除旧页、装入新页及计数更新后，才写标准错误日志。日志写入或流关闭故障转为 `ExecuteError` 并保留原因，此时缓存替换已经完整完成，后续命中仍可正常使用。

- `read_page()` 返回磁盘快照，可以看不到尚未刷写的脏页修改。
- `write_page()` 整页写入成功后移除旧缓存，旧脏对象不能再覆盖新内容。
- `get_page()` 未命中时先完整读取目标页，再处理牺牲页；脏页写回失败则保留原缓存对象。
- `flush_page()`／`flush_all()` 使用私有写入通道，成功才清脏，不改变替换顺序。
- `close()` 尝试刷盘并释放句柄，优先传播最早故障；正常关闭可重复调用。关闭后仅允许读取统计和再次关闭。

**页引用的生命周期是与 B 联调的关键**：修改后立即设置 `dirty=True`；调用可能访问其他页的方法后，不再修改旧引用，必须重新 `get_page()`。遍历或产生记录前先复制下一页号、记录字节等不可变数据。

释放页采用空闲链头插法；分配优先取链首，否则追加文件。空闲页前四字节保存下一页号，其余清零。每次从最新页数据校验链的越界、页 0、循环、重复释放和保留区域，不使用永不刷新的空闲集合。B 必须保证释放前已解除表链引用，C 不解析用户表链。

复用时先更新并刷写页 0 的空闲链首，再清零被取出的页；失败可能泄漏页，但不能把清零后的页继续挂在空闲链中。对页 0 的修改只涉及偏移 8 的四个字节，重新取得最新缓存页后修改，保留 B 的表数和映射。

## 运行测试

通常在仓库根目录执行 `python -m pytest -q`，或在工程目录执行同一命令。

若本机旧临时目录存在权限问题，可使用工作区内全新的测试目录，关闭缓存插件，不需要改变产品代码：

```powershell
$env:PYTHONUTF8 = '1'
New-Item -ItemType Directory -Path test-output -Force | Out-Null
$testRunPath = Join-Path (Get-Location) ('test-output/c-' + [guid]::NewGuid().ToString('N'))
python -m pytest -q -p no:cacheprovider --basetemp $testRunPath
```

2026-09-09 修复审查发现后，本地完整回归：**391 项通过**，差异格式检查通过。新增 12 项回归覆盖长链、诊断定位和日志故障，其中 11 项确认在旧实现失败，另一项固定左右遍历顺序。实际运行版本为 Python 3.13.1；另外已做 Python 3.11 语法解析检查，但不能把语法检查等同于 3.11 运行测试。现有持续集成配置包含对应版本，远程执行结果待团队确认。

新增测试分别覆盖类型、语义、Catalog、页存储、公共样例和独立进程重启。M1 构造测试已定向更新：C 构造可以真实加载或建页，B 未实现的接口仍应明确抛出存根异常；公共签名和无导入副作用检查保留。

## 答辩准备

应能独立解释：为何语义不建表；为何快照没有后端引用；为何 VARCHAR 计算字节；为何负数除法不能直接用向下取整；为何刷盘不能调用公开整页覆盖方法；为何容量 1 会让旧页引用失效；为何系统目录每列一行不会受单个 JSON 字段 255 字节限制。

典型失败案例已转成测试：两个 INSERT 值同时错误、替换 JSON 失败、脏页淘汰失败、直接写盘后旧缓存覆盖风险、损坏空闲链、缺失系统目录。实现和测试由 AI 辅助编写；提交和答辩前由 C 负责人逐模块复核，源码完成、测试通过和团队审阅分别记录。
