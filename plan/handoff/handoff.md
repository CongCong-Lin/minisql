## 1. 项目背景

中南大学计算机学院《大型平台软件设计实习》（姚鑫、邓磊、桂宁）。任务是四人协作，分三个阶段构建一个可持久化的小型数据库，贯通编译原理、操作系统和数据库课程。

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 一：SQL 编译器 | 词法 → 语法 → 语义 → 逻辑计划与优化 | 可先独立开发 |
| 二：页式存储 | 4KB 页读写与 LRU/FIFO 缓存 | 可与阶段一并行 |
| 三：数据库系统 | 执行引擎、存储引擎、系统目录及持久化 | 依赖阶段一、二的接口与实现 |

必做 SQL 为 CREATE TABLE、INSERT、SELECT（含 WHERE）、DELETE。核心验收要求是**正常关闭并重启后，表结构和数据均可恢复**。

课程允许使用大模型辅助，但考核每个人是否掌握代码：隐藏测试、随机点名讲函数、现场加需求、定位错误所属阶段，都需要成员独立说明和操作。每个人必须理解本人模块的数据流、接口和实现依据。

| **A** | 词法分析器 | 命令行接入 | 命令行、用例执行器、端到端测试与公共用例库 |

## 4. v1.5 关键裁决

以下为接手时需要掌握的摘要。具体签名、字段和二进制布局见[接口契约](contracts.md)。

### 4.1 词法、分段与语法

- Token 保存 `type/lexeme/line/column`；保留原始词素，Catalog 查找时统一名字大小写。关键词共 **23 个**，NULL 在词法识别、语法阶段拒绝。
- `tokenize(text)` 完整扫描一次：成功返回有效 Token 与唯一全局 EOF；失败抛出聚合 `LexerError`，其中 `errors` 保存全部诊断，`tokens` 保存有效 Token 与全局 EOF。非法字符恢复后继续扫描，未闭合字符串与注释按契约恢复。
- `run()` 只根据分号 **Token** 分段，不能按原始文本中的分号切割。每段附加局部 EOF，Token 和错误保留全文件行列号。含词法错误的段直接失败；语法分析器对其他段首错抛出，由 `run()` 继续后续段。
- 最后一条语句也必须以分号结束。缺分号会使当前整个分段失败，越过下一分号再继续，不保留该分段中的第二个语句起始词。空输入返回空结果；单独的分号是语法错误。
- 使用递归下降。表达式优先级从高到低为括号、乘除、加减、比较、NOT、AND、OR。包含算术表达式与 TRUE/FALSE；每个 AST 节点携带源码位置。
- 非终结符入口失败时，期望集合从产生式的 FIRST 集推导；匹配特定终结符失败时，列出正在期待的终结符。诊断集合的顺序固定。

### 4.2 语义、算术与优化

- 类型规则唯一存放于 `sql_compiler/types.py`。字面量转换由语法分析器负责，INT 字面量边界、有限浮点值按契约检查；VARCHAR 按 UTF-8 字节数限制为 255。
- INSERT 目标列必须无重复且完整覆盖表列，允许顺序不同；执行时按表结构顺序还原行。逐列类型检查收集全部不匹配诊断。
- `analyze()` 只检查并作语义标注，不注册表或持久化。语法阶段完成后保存 AST 结构快照，语义标注不进入展示 JSON。
- INT 运算采用有符号 32 位，整数除法向零截断。除零和运算溢出只在实际求值时报执行错误。AND、OR 从左到右短路。
- 优化器返回新计划，不修改原始计划。常量折叠遇除零或溢出时保留原子树；`x AND FALSE`、`x OR TRUE` 仅在折叠后的 `x` 不含算术节点时消除。规则按首次触发顺序去重，循环至不动点，优化前后结果及执行错误行为须一致。
- SELECT 计划为 `Project → Filter（可选）→ SeqScan`；无 WHERE 时省略 Filter，`SELECT *` 的投影列仍表示为 `"*"`。

### 4.3 顶层接口、结果与 Catalog

应用提交 SQL 的统一入口是 `run(text, catalog, storage=None)`。初始化、关闭分别调用 `open_database()`、`close_database()`；`compile_sql()` 是独立纯编译接口，命令行不直接拼装编译器和执行器调用。

| 调用或模式 | 建表与目录行为 |
|---|---|
| `analyze()` | 只检查，不注册表。 |
| `compile_sql()` | 在目录内存快照上编译；成功建表对该调用后续语句可见，不写真实目录，遇首个失败语句抛异常。 |
| `run(storage=None)` | 阶段一教学模式；单条 CREATE 完成全部编译阶段后由 `run()` 提交传入 Catalog，后续语句可见。CLI 的 compiler 模式持久化 JSON，内存 Catalog 不写盘。 |
| 数据库模式 | 执行器只调用一次 `Catalog.create_table()`，由 Catalog 完成物理建表与系统目录登记；写入、刷盘成功后更新内存目录。 |

`StmtResult` 保留 `ok/error/tokens/ast/plans/exec_result` 六个字段，增加 `semantic_ok: bool | None`。结果保留已经完成阶段的产物：词法失败无展示产物；语法失败保留 Token；语义失败保留 Token 和 AST；执行失败保留原始、优化两份计划。`run()` 只返回数据，不打印，捕获语句级错误后继续后续语句。

编译异常共享 `CompileError` 类型身份，执行异常使用 `ExecuteError`。编译诊断格式为 `[STAGE] Error at line X, column Y: reason`；执行诊断为 `[EXECUTE] Error: reason`。多条诊断按源码位置排序，以换行连接存于 `error`。模块不得用返回值代替异常表达失败，也不得自行打印诊断。

### 4.4 存储、记录与系统目录

- B 提供表级创建、存在性检查、插入、扫描、按记录标识删除、刷盘与关闭接口。记录标识为 `(页号, 槽号)`；扫描与过滤在内部保留该标识，完整行按 Catalog 列序排列。最终查询行为 Python 元组，按 SELECT 列序投影，`*` 则保持 Catalog 列序。DELETE 先完成筛选，再标记删除。
- C 保留七个页接口，增加 `flush_all()` 和 `close()`。正常访问经过缓存；直接写盘成功后使对应缓存失效；关闭前写回全部脏页。默认缓存为 64 页、LRU 策略；日志和统计输出到标准错误。
- 页大小为 4096 字节，数据页头为 16 字节，槽目录从页尾生长。单条序列化记录上限为 **4076 字节**，超限须在修改或分配页前拒绝。
- 删除仅将槽中记录偏移设为 `0xFFFF`，已分配槽数不减少；记录头固定为 0。本版不复用墓碑槽。插入向表尾追加，空间不足再分配新页。
- 页 0 保存固定全局元数据及 60 个表映射条目，包含系统表，最多 **59 张用户表**。B 管表数、表映射与表内页链，C 管空闲页链首及物理页分配；精确布局以契约为准。
- 系统目录为 `__catalog__(table_name, column_name, column_type, ordinal, source_line, source_column)`，每列一条记录，`ordinal` 从 0 开始。内部结构直接定义，不读取自身描述，也不保存系统表自身的列记录。
- 新库依次初始化页 0、打开存储引擎、建立系统目录、加载 Catalog；已有数据库缺少系统目录时报损坏。用户 SQL 不得创建或访问 `__catalog__`，用户表列表不包含系统表。

### 4.5 命令行与验收

- Python 3.11+，依赖仅 pytest。命令行提供 `--mode compiler|database`，默认 `database`；`--data-dir` 默认为 `data`。两模式分别使用 `catalog.json` 和 `minisql.db`，不隐式迁移数据。
- 使用批处理输入：文件或标准输入均按 UTF-8 读至 EOF，允许 BOM，并统一换行。四个展示开关默认开启，同时提供相应 `--no-*` 开关；重复指定时最后一个生效。
- 标准输出采用 UTF-8、LF，固定顺序为 Token、AST、语义成功提示、原始计划、优化计划、查询表头、查询行、执行消息；错误出现在已完成阶段产物之后。前缀与 JSON 的唯一格式见契约，不能由命令行自行选择。
- 命令行展示全部结果后退出：全部成功为 0，存在 SQL 失败为 1；参数、文件及数据库初始化或关闭失败输出到标准错误并退出 2。调试、缓存日志与统计不进入标准输出。
- 用例采用 `tests/cases/<套件>/<名称>.sql` 与同名 `.expected`，套件分 compiler、execution；期望文件记录完整标准输出及末行 `EXIT: <code>`。A 的执行器先统一 CRLF/CR 为 LF、忽略末尾多余 LF，其余字节精确比对；EXIT 行不由 CLI 打印。
- 每人至少 15 条、总计至少 60 条用例，每人及总库错误用例**不少于一半**；阶段一 compiler 套件满足该门槛，后续追加执行用例。同一用例不重复计数。普通用例隔离临时数据库，只有同一重启测试的不同步骤复用目录。
- 验收覆盖：跨语句恢复与全文件位置、NOT/NULL/FIRST、INSERT 列完整性、各阶段失败产物、目录更新时点、长列名重启恢复、59/60 张用户表边界、4076/4077 字节记录边界、删除及跨页扫描、缓存容量为 1、优化前后错误一致、命令行开关及固定输出。详细场景见契约与分工文档。

## 5. 并行开发方式

在公共类型与接口存根就位后，下游使用契约数据和测试替身开发，无需等待上游完整实现：B 构造 Token 测试语法；C 构造 AST 测试语义；D 使用 Catalog 和存储接口替身测试计划、编排与执行。

阶段二的物理页与缓存由 C 开发，B 的序列化和表级操作通过页接口替身并行推进。A 维护输入输出样例和用例执行器，D 负责持续集成接入及最终联调。允许导入公共类型并不意味着可以依赖对方的私有实现。
